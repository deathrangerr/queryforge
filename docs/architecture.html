Component Breakdown

Frontend (React + Vite)

File Structure:

src/
├── App.jsx          # Main application component
├── App.css          # Styling with CSS variables for theming
├── main.jsx         # React entry point
index.html           # HTML template
vite.config.js       # Vite configuration
.env                 # Frontend environment variables

Key Components:

  • LoginPage: SAML authentication initiation
  • ConnectionWizard: Database connection form
  • Toolbar: Navigation tabs and user menu
  • Sidebar: Schema browser with collapsible tree
  • SQLEditor: Query editor with execution controls
  • DataViewer: Table data display with pagination
  • PropertiesViewer: Table schema information
  • HistoryViewer: Query history display
  • Notification: Toast notifications
  • Modal: Confirmation dialogs

Backend (Express.js)

File Structure:

server.js            # Express server with all routes
.env.server          # Backend environment variables
saml-config.json     # SAML IdP configuration
package.json         # Dependencies

Core Modules:

  • Authentication: SAML 2.0 with Passport.js
  • Session Management: In-memory sessions with timeouts
  • QueryForges: Connection pool per session
  • Query Execution: Validation and transaction handling
  • Schema Operations: Metadata retrieval
  • Export Functions: Data format conversion

Data Flow

1. Authentication Flow

User → Login Page → SAML Redirect → Identity Provider
                                           ↓
                                    User Authenticates
                                           ↓
                                    SAML Assertion
                                           ↓
Backend ← SAML Callback ← Identity Provider
   ↓
Create Session
   ↓
Redirect to App → User Logged In

2. Database Connection Flow

User → Connection Form → Submit Credentials
                              ↓
                         Backend Validates
                              ↓
                    Create DB Client (pg/mysql2/oracledb)
                              ↓
                         Test Connection
                              ↓
                    Store in dbClients Map
                              ↓
                    Return Success → Frontend Updates State

3. Query Execution Flow

User → SQL Editor → Execute Query
                         ↓
                    Validate Query
                         ↓
                  Is Mutating? ──No──→ Execute Directly
                         │                    ↓
                        Yes              Return Results
                         ↓
                  Show Confirmation
                         ↓
                  User Confirms?
                         ↓
                   BEGIN Transaction
                         ↓
                   Execute Query
                         ↓
                Success? ──No──→ ROLLBACK
                    │                ↓
                   Yes          Show Error
                    ↓
              Return Results
                    ↓
           User COMMIT/ROLLBACK

State Management

Frontend State (React useState)

State Variable Type Purpose
user Object Authenticated user information
connected Boolean Database connection status
view String Active tab (sql/data/properties/history)
schema Array Database schema structure
results Object Query execution results
pendingTransaction Boolean Active transaction flag
darkMode Boolean Theme preference (persisted)
loading Boolean Loading state for operations
notificationHistory Array Past notifications (last 20)
abortController Object Query cancellation controller

Backend State (In-Memory Maps)

Map Name Key Value Purpose
activeSessions email sessionID Single session enforcement
dbClients sessionID {type, client/conn} Database connections
sessionTimeouts sessionID timeoutID Inactivity timers

Technology Stack

Frontend

  • React 18: UI framework
  • Vite: Build tool and dev server
  • CSS Variables: Theming system
  • Fetch API: HTTP requests

Backend

  • Node.js: Runtime environment
  • Express.js: Web framework
  • Passport.js: Authentication middleware
  • @node-saml/passport-saml: SAML strategy
  • express-session: Session management

Database Drivers

  • pg: PostgreSQL client
  • mysql2: MySQL client
  • oracledb: Oracle client

Security

  • SAML 2.0: Enterprise SSO
  • CORS: Cross-origin protection
  • Session Cookies: Secure authentication
  • Environment Variables: Secret management

Design Patterns

1. Single Page Application (SPA)

React-based SPA with client-side routing and state management.

2. RESTful API

Backend exposes REST endpoints for all operations.

3. Session-Based Authentication

Server-side sessions with SAML for enterprise SSO.

4. Connection Pooling

One database connection per user session, stored in Map.

5. Optimistic UI Updates

Immediate feedback with loading states and error handling.
