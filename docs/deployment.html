Production Setup, Scaling, and Monitoring

Prerequisites

System Requirements

  • Node.js: Version 18.x or higher
  • Memory: Minimum 2GB RAM
  • Storage: 500MB for application + logs
  • Network: Access to database servers

Database Drivers

  • PostgreSQL: pg (included)
  • MySQL: mysql2 (included)
  • Oracle: oracledb (requires Oracle Instant Client)

Installation Steps

1. Clone Repository

git clone <repository-url> cd dbclient

2. Install Dependencies

npm install

3. Configure Environment

Create .env file:

# Application Environment APP_ENV=production # Session Configuration SESSION_SECRET=<generate-strong-random-secret> SESSION_TIMEOUT=300000 SESSION_MAX_AGE=3600000 # Server Configuration PORT=3000

Create .env.server file:

# Server Binding HOST=0.0.0.0 PORT=3000

4. Configure SAML

Create saml-config.json:

{ "entryPoint": "https://your-idp.example.com/sso/saml", "issuer": "database-client", "callbackUrl": "https://your-app-domain.com/auth/saml/callback", "cert": "-----BEGIN CERTIFICATE-----\n...\n-----END CERTIFICATE-----" }

5. Build Frontend

npm run build

6. Start Server

node server.js

Production Deployment

Using PM2 (Recommended)

# Install PM2 npm install -g pm2 # Start application pm2 start server.js --name dbclient # Enable startup script pm2 startup pm2 save # Monitor pm2 monit # View logs pm2 logs dbclient

PM2 Ecosystem File

Create ecosystem.config.js:

module.exports = { apps: [{ name: 'dbclient', script: 'server.js', instances: 2, exec_mode: 'cluster', env: { NODE_ENV: 'production', PORT: 3000 }, error_file: './logs/pm2-error.log', out_file: './logs/pm2-out.log', log_date_format: 'YYYY-MM-DD HH:mm:ss Z', max_memory_restart: '1G' }] };
# Start with ecosystem file pm2 start ecosystem.config.js

Reverse Proxy Setup

Nginx Configuration

server { listen 80; server_name your-domain.com; # Redirect to HTTPS return 301 https://$server_name$request_uri; } server { listen 443 ssl http2; server_name your-domain.com; ssl_certificate /path/to/cert.pem; ssl_certificate_key /path/to/key.pem; # Security headers add_header X-Frame-Options "SAMEORIGIN" always; add_header X-Content-Type-Options "nosniff" always; add_header X-XSS-Protection "1; mode=block" always; location / { proxy_pass http://localhost:3000; proxy_http_version 1.1; proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection 'upgrade'; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; proxy_cache_bypass $http_upgrade; # Timeouts for long queries proxy_connect_timeout 600; proxy_send_timeout 600; proxy_read_timeout 600; send_timeout 600; } }

Docker Deployment

Dockerfile

FROM node:18-alpine WORKDIR /app # Copy package files COPY package*.json ./ # Install dependencies RUN npm ci --only=production # Copy application files COPY . . # Build frontend RUN npm run build # Create logs directory RUN mkdir -p logs # Expose port EXPOSE 3000 # Start application CMD ["node", "server.js"]

Docker Compose

version: '3.8' services: dbclient: build: . ports: - "3000:3000" environment: - NODE_ENV=production - APP_ENV=production env_file: - .env - .env.server volumes: - ./logs:/app/logs - ./saml-config.json:/app/saml-config.json:ro restart: unless-stopped healthcheck: test: ["CMD", "wget", "--quiet", "--tries=1", "--spider", "http://localhost:3000/health"] interval: 30s timeout: 10s retries: 3

Build and Run

# Build image docker-compose build # Start container docker-compose up -d # View logs docker-compose logs -f # Stop container docker-compose down

Monitoring & Logging

Application Logs

  • Activity Log: logs/activity-YYYY-MM-DD.log
  • Security Log: logs/security-YYYY-MM-DD.log
  • Error Log: logs/error-YYYY-MM-DD.log

Log Rotation

Logs automatically rotate daily. Configure retention in server.js:

maxFiles: '30d' // Keep logs for 30 days

Health Check Endpoint

GET /health Response: { "status": "ok", "timestamp": "2026-02-19T11:22:00.000Z" }

Monitoring Metrics

  • Active sessions count
  • Query execution times
  • Error rates
  • Memory usage
  • CPU usage

Security Hardening

Environment Variables

⚠️ Critical:
  • Never commit .env files to version control
  • Use strong random SESSION_SECRET (32+ characters)
  • Rotate SESSION_SECRET periodically
  • Restrict file permissions: chmod 600 .env*

HTTPS Only

  • Always use HTTPS in production
  • Use valid SSL certificates (Let's Encrypt recommended)
  • Enable HSTS headers
  • Disable HTTP access

Firewall Rules

  • Allow only necessary ports (443 for HTTPS)
  • Restrict database access to application server only
  • Use security groups/network ACLs
  • Enable fail2ban for brute force protection

Backup & Recovery

What to Backup

  • Configuration: .env, .env.server, saml-config.json
  • Logs: logs/ directory (for compliance)
  • Application: Entire codebase

Backup Script

#!/bin/bash DATE=$(date +%Y%m%d) BACKUP_DIR="/backups/dbclient" # Create backup directory mkdir -p $BACKUP_DIR # Backup logs tar -czf $BACKUP_DIR/logs-$DATE.tar.gz logs/ # Backup configuration (encrypted) tar -czf - .env* saml-config.json | \ openssl enc -aes-256-cbc -salt -out $BACKUP_DIR/config-$DATE.tar.gz.enc # Keep only last 30 days find $BACKUP_DIR -name "*.tar.gz*" -mtime +30 -delete

Scaling Considerations

Horizontal Scaling

  • Use PM2 cluster mode for multiple instances
  • Deploy behind load balancer (ALB, Nginx)
  • Enable sticky sessions for session persistence
  • Consider Redis for shared session storage

Performance Tuning

  • Adjust max_memory_restart in PM2
  • Configure database connection pooling
  • Enable gzip compression in Nginx
  • Use CDN for static assets

Database Connections

  • Each user session = 1 database connection
  • Plan database connection limits accordingly
  • Monitor connection pool usage
  • Set appropriate timeouts

Troubleshooting

Common Issues

Application won't start

  • Check .env files exist and are readable
  • Verify saml-config.json is valid JSON
  • Ensure port 3000 is not in use
  • Check Node.js version (18+)

SAML authentication fails

  • Verify callbackUrl matches IdP configuration
  • Check certificate is correct and not expired
  • Ensure HTTPS is enabled
  • Review security logs

Database connection fails

  • Verify network connectivity to database
  • Check firewall rules
  • Confirm credentials are correct
  • Ensure database driver is installed

Debug Mode

# Enable debug logging DEBUG=* node server.js # Or with PM2 pm2 start server.js --name dbclient --log-date-format 'YYYY-MM-DD HH:mm:ss Z'

Maintenance

Regular Tasks

  • Daily: Monitor logs for errors
  • Weekly: Review security logs, check disk space
  • Monthly: Update dependencies, rotate secrets
  • Quarterly: Security audit, performance review

Update Procedure

# Backup current version tar -czf dbclient-backup-$(date +%Y%m%d).tar.gz . # Pull latest code git pull # Install dependencies npm install # Rebuild frontend npm run build # Restart application pm2 restart dbclient
