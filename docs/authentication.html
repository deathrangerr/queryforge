SAML 2.0 Authentication

The application uses SAML 2.0 for enterprise single sign-on.

Configuration

{ "entryPoint": "https://your-idp.example.com/sso/saml", "issuer": "database-client", "callbackUrl": "https://your-app-domain.com/auth/saml/callback", "cert": "-----BEGIN CERTIFICATE-----\n...\n-----END CERTIFICATE-----" }

Authentication Flow

  1. User accesses the application
  2. Redirected to SAML Identity Provider
  3. User authenticates with corporate credentials
  4. SAML assertion returned to callback URL
  5. Session created with user attributes
  6. User redirected to application

Session Management

Session Lifecycle

  • Inactivity Timeout: 5 minutes
  • Maximum Duration: 60 minutes
  • Single Session: One active session per user
  • Query Protection: Sessions extended during query execution

Session Storage

Sessions are stored server-side with the following attributes:

  • User email (from SAML assertion)
  • Database connection details
  • Last activity timestamp
  • Session creation time
  • Active transaction state

Database Credentials

User Credentials Approach

Each user provides their own database credentials - no shared accounts.

Security Benefits:
  • Individual accountability for all database operations
  • Audit trails tied to specific users
  • No credential sharing or rotation issues
  • Database-level access control enforcement

Credential Storage

  • Credentials stored in server-side session only
  • Never persisted to disk or database
  • Cleared on session expiration
  • Not logged or transmitted to client

Security Features

Query Safety

  • Destructive Query Confirmation: Prompts for DELETE, DROP, TRUNCATE
  • Transaction Management: Explicit BEGIN/COMMIT/ROLLBACK
  • Auto-Rollback: Errors automatically rollback transactions
  • Read-Only Mode: Optional mode to prevent mutations

Environment Protection

  • Environment Banner: Visual indicator (DEV/UAT/PROD)
  • Color Coding: Green (DEV), Yellow (UAT), Red (PROD)
  • Risk Analysis: Automatic detection of risky queries

Logging & Audit

  • All queries logged with user, timestamp, and result
  • Security events (login, logout, session kill) logged
  • Export operations tracked
  • Failed authentication attempts logged

Access Control

Application Level

  • SAML authentication required for all access
  • No anonymous or guest access
  • Session validation on every request

Database Level

  • User's own database credentials used
  • Database-native access control enforced
  • No privilege escalation possible
  • Users limited to their granted permissions

DBA Tools

  • Session monitoring and termination
  • Lock monitoring
  • User/role management viewing
  • All DBA actions logged

Best Practices

⚠️ Security Recommendations

  • Use strong database passwords (12+ characters)
  • Enable MFA on SAML identity provider
  • Regularly review activity logs
  • Use read-only mode for production queries
  • Always test destructive queries in DEV first
  • Use transactions for multi-statement operations
  • Log out when finished
  • Never share database credentials
